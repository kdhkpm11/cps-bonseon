# 하루쌤 2.0 — 기술 구현 (답안 제출용)

우리는 하루쌤 2.0의 판단 규칙을 문서로만 기술하지 않고, 실제로 동작하는 파이썬 엔진으로 구현한 뒤 웹 플랫폼으로 배포하였습니다. 아래에 제시하는 처리 결과와 검증 수치는 모두 이 엔진을 직접 실행하여 얻은 실측값입니다.

## 1. 구현 개요

핵심 설계 사상은 다음과 같습니다. 인공지능은 신호를 읽어 잠정적인 가설만 세우고, 최종 판단은 규칙과 학생의 목소리가 합의하여 정합니다. 이 사상을 구현으로 옮기기 위하여, 우리는 판단 논리를 부작용이 없는 순수 함수로 작성하여 같은 입력에 대해서는 언제나 같은 결과가 나오도록 보장하였습니다. 또한 외부의 기계학습 프레임워크에 의존하지 않고 파이썬 표준 라이브러리만으로 구현하여, 판단이 이루어지는 과정을 사람이 한 줄씩 그대로 따라 읽을 수 있게 하였습니다.

## 2. 기술 스택

| 구분 | 사용 기술 | 선택한 이유 |
|---|---|---|
| 언어 | Python 3 | 규칙을 그대로 읽어 검증하기 쉽고, 배포가 간단하기 때문입니다 |
| 의존성 | 표준 라이브러리(dataclasses, typing, random, math, statistics)만 사용 | 외부 학습 프레임워크를 배제하여 판단의 해석 가능성과 재현성을 확보하기 위해서입니다 |
| 판단 논리 | 순수 함수 규칙 엔진 | 부작용이 없어 같은 입력에 같은 결과를 돌려주므로, 설명과 검증이 모두 쉽기 때문입니다 |
| 데이터 모델 | dataclass (Student, Voice) | 학생의 신호와 목소리를 명시적인 자료 구조로 분리하기 위해서입니다 |
| 학습상태 추적 | Knowledge Tracing 방식의 추세 추적 | 고정된 라벨 대신 최근 궤적으로 상태를 읽어 낙인 고착을 막기 위해서입니다 |
| 유예 판단 | Selective Prediction 및 Conformal 방식 | 20퍼센트라는 유예 예산을 사람이 임의로 정하지 않고 데이터가 보정하도록 하기 위해서입니다 |
| 2차 소견 | kNN 기반 유사 또래 경로 참조 | 집단의 통계를 참고 의견으로만 쓰고 개인 판단을 확정하지 못하게 하기 위해서입니다 |
| 배포 | fly.io | 심사위원이 상시 접속하여 직접 조작할 수 있게 하기 위해서입니다 |

구현은 `sim/` 아래 네 개의 모듈로 나뉩니다. `haruel2.py`는 핵심 판단 엔진이고, `haruel2_bigdata.py`는 대규모 데이터를 종합하는 확장 엔진이며, `negotiate.py`는 학생과의 다중 턴 대화 협상을 담당하고, `stress_test.py`는 대량의 가상 학생으로 안전성과 공정성을 검증합니다.

## 3. 알고리즘 구조: 3층 협의 파이프라인

하루쌤 2.0의 판단은 신호에서 시작하여 학생의 목소리를 거쳐 합의에 이르는 세 층으로 이루어집니다. 전체 흐름은 아래와 같으며, 손으로 그릴 수 있는 구조도로 나타냈습니다.

```
[신호 입력]                     [1층] AI 가설            [2층] 학생 목소리        [3층] 합의·예산·공개
정답률·추세                  ┌──────────────┐        ┌──────────────┐      ┌──────────────┐
오답반복률      ─────────▶  │ ai_hypothesis │  ───▶  │  reconcile    │ ──▶ │ apply_budget │
과제제출률                  │ 잠정판단+확신도│        │ 목표·맥락 선언 │      │ 20% 예산 보정 │
자기진단                    │ 필요시 질문   │        │ 질문에 학생응답│      │ governance   │
(접속·카메라 배제)          └──────────────┘        └──────────────┘      │ 수신자별 공개 │
                                                                          └──────────────┘
             결과: 자동추천 / 판단보류 / 교사검토  +  판단 근거 한 줄  +  협의 기록
```

**1층 (AI 가설, `ai_hypothesis`).** 엔진은 핵심 신호만으로 잠정 판단과 확신도를 산출합니다. 이때 규칙은 다음 순서로 적용됩니다. 정서위기 신호가 있으면 확신도와 무관하게 교사검토로 보내고, 높은 정답률과 피로가 함께 나타나면 증량이 아니라 학습량 감축을 자동으로 추천하며, 협업 과제의 답안 유사성은 부정행위로 자동 판정하지 않습니다. 회피 성향이 보이면 소량의 탐색 과제를 제안하고, 상승 추세가 뚜렷하면 낮은 절대값에도 상향을 격려하며, 이해가 취약하면 기초를 보강합니다. 어느 규칙에도 뚜렷이 들어맞지 않아 신호가 애매할 때에는 판단을 교사에게 넘기지 않고 학생에게 한 문항을 질문합니다.

**2층 (학생 목소리, `reconcile`).** 학생이 선언한 목소리가 1층의 가설을 수정하거나 확정합니다. 학생이 맥락을 선언하면(예를 들어 집에 컴퓨터가 없다거나 한국어 문장이 어렵다는 진술) 엔진은 환경이나 언어에 종속된 해석을 무효로 돌리고, 학생이 목표를 선언하면(도전, 휴식, 기초 가운데 하나) 그동안 행동으로 추론하던 의도를 직접 반영합니다. 다만 정서위기로 분류된 안전 사안만은 어떤 목소리로도 뒤집을 수 없습니다.

**3층 (합의와 공개).** 유예 예산 함수가 판단보류와 교사검토의 비율을 20퍼센트 이하로 유지하되, 정서위기 학생은 예산을 맞추기 위한 자동 전환의 대상에서 제외합니다. 마지막으로 거버넌스 함수가 감정과 같은 민감 정보를 수신자에 따라 다른 수준으로 공개합니다.

## 4. 핵심 결정 함수 (실제 소스)

판단의 뼈대는 아래의 순수 함수이며, 부작용이 없으므로 같은 입력에 대해서는 언제나 같은 결과를 돌려줍니다.

```python
def decide(s):
    return reconcile(s, ai_hypothesis(s))   # 신호로 가설 → 학생 목소리로 합의

# 1층: 신호만으로 잠정 판단 + 확신도 (일부)
def ai_hypothesis(s):
    acc, tr = s.acc_hist[-1], slope(s.acc_hist)     # 현재 정답률과 추세
    if s.self_report == "crisis":                   # 정서위기 → 사람에게(안전 최우선)
        return dict(kind="교사검토", ...)
    if s.self_report == "tired" and acc >= 0.85:    # 고성과+피로 → 증량이 아니라 감축
        return dict(kind="자동추천", rec="증량 중단 → 학습량 감축", ...)
    if tr >= 0.03 and s.submit_rate >= 0.6:         # 성장 추세 → 상향(라벨 고착 배제)
        return dict(kind="자동추천", ...)

# 2층: 학생 목소리로 환경·언어 프록시 해석을 무효화 (일부)
def reconcile(s, h):
    if h["kind"] == "교사검토":                     # 안전 사안은 목소리로 못 덮음
        return ("교사검토", ...)
    if "한국어" in s.voice.context:                 # 학생이 언어 장벽을 선언 → 능력 단정 안 함
        return ("자동추천", "언어 지원(읽기보조)+계산·문장형 분리 측정", ...)
```

## 5. 대규모 데이터 종합 판단과 오프퀄 가드레일

확장 엔진(`haruel2_bigdata.py`)은 하나의 기법에 의존하지 않고 여섯 갈래의 소견을 종합합니다. 곧 개인의 학습 궤적, 규칙 엔진의 1차 판단, 유사 또래 6천 명의 kNN 경로, 참조 집단 대비 백분위 위치, Conformal 방식으로 계산한 애매도, 그리고 학생과의 협의입니다. 이때 유사 또래의 경로와 백분위는 교사에게 제시되는 2차 소견에 머무르며, 개인의 궤적과 목소리가 언제나 우선합니다. 우리는 이 장치를 오프퀄 가드레일이라 부릅니다. 2020년 영국의 오프퀄이 시험을 취소한 뒤 학교의 과거 통계로 개인의 등급을 산정하였다가 저소득층 학생을 대규모로 강등시킨 사건이, 집단 통계로 개인을 확정하는 일의 위험을 실제로 보여 주었기 때문입니다. 아울러 20퍼센트라는 유예 예산의 문턱은 사람이 임의로 정하지 않고, 6천 명 참조 집단의 애매도 분포에서 데이터가 스스로 계산하도록 하였습니다.

## 6. 대량 스트레스 검증 (실측)

우리는 열 건의 민원과 신규 학생 세 명을 넘어, 약 200만 명의 가상 학생을 생성하여 하루쌤 2.0이 안전과 공정의 원칙을 실제로 지키는지 측정하였습니다. 아래는 `stress_test.py`를 실행하여 나온 실측값입니다.

| 검증 항목 | 실측 결과 |
|---|---|
| 표본 규모 | 1,999,999명 |
| 처리 분포 | 자동추천 93.3% · 판단보류 3.7% · 교사검토 3.0% |
| 유예 예산 | 판단보류와 교사검토의 합이 6.68%로 20퍼센트 이하 |
| 안전 누락(정서위기 미에스컬레이션) | 0건 |
| 환경 프록시 불이익 | 0건 (접속·카메라가 판단에 없어 구조적으로 보장) |
| 명확 사례 판단 일치율 | 100.00% |
| 종합 방어율(안전·공정 위반이 하나도 없는 비율) | 99.81% |

특히 환경 프록시 불이익이 0건인 까닭은, 같은 학생의 접속 시간이나 카메라 값을 바꾸어도 판단이 변하지 않는 불변성을 코드가 구조적으로 보장하기 때문입니다. 곧 이 지표들이 애초에 판단 함수의 입력에 존재하지 않습니다.
