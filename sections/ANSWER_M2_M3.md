# 미션2 — 하루쌤 2.0 설계
════════════════════════════════════════════════════════════

## 2-0. 한 줄 결론
하루쌤의 결함은 **정보 부족이 아니라 해석의 오류**다. 그래서 2.0은 새 데이터를 더 모으지 않고 **(C7)** 오직 **해석 규칙을 교체**한다: 「AI는 신호만 읽고, 최종 판단은 규칙·학생·데이터의 합의가 정한다.」

## 2-1. 사용 정보 선택  (C1·C2·C7)
**핵심 신호 4개(직접 판단에 사용)** — (C1: 3개 이상 충족)

| 신호 | 역할 | 근거 |
|---|---|---|
| 정답률 + **추세** | 수준·성장 방향 | ∵ 절대값 아닌 궤적(신규A 41→58 상승=성장) |
| 오답 반복률 | 이해 vs 실수 구분 | ∵ 정답률 단독 단정 방지 |
| 과제 제출률 | 참여 지속성 | ∵ 단, 접속시간과 분리 |
| 자기진단(감정) | 정서·번아웃 감지 | ∵ 정량지표가 놓친 맥락(준호 과부하) |

**보조 신호(단독 판단 금지, 결합으로만)**: 풀이시간(∵서율·아민), 힌트횟수(∵도윤)
**배제 신호(직접 판단 불가) — (C2)**:
- 접속시간 — ∵ 가정환경(PC 유무)에 종속 → 의지 판단에 쓰면 저소득층 차별
- 카메라 집중도 — ∵ 주거환경 종속 + 사생활 침해 + 추정 부정확 → 완전 배제
> (C7) 새로 수집하는 신호는 **0개**. 기존 신호의 해석 규칙만 바꾼다.

## 2-2. 판단 5원칙  (C5: 하나의 정보로 확정 금지)
1. **다지표 교차** — 어떤 판단도 2개 이상 신호가 같은 방향일 때만.
2. **추세 > 상태** — 최근 궤적을 현재값보다 우선(라벨 고착 배제).
3. **맥락 보정** — 환경 프록시(접속·카메라·풀이시간)를 능력·의지 판단에서 제외.
4. **행동 의도 구분** — 힌트·협업은 유익 가능 → 부정 신호로 자동 처벌 금지.
5. **정보 거버넌스** — 감정 등 민감정보는 수신자별 공개 수준을 통제.

## 2-3. 3구분 판단체계  (C3: 대부분 자동 · C4: 보류+교사 ≤20%)
처리 유형: **자동추천 / 판단보류 / 교사검토**. 결정은 아래 규칙이 정한다(순수 함수, 같은 입력=같은 결과).
```
① 정서위기 신호        → 교사검토   # 안전 최우선(어떤 목소리로도 못 덮음)
② 맥락·언어 불확실     → 판단보류   # 정보 불충분
③ 2개+ 신호 일치·추세 → 자동추천   # 대부분(C3)
④ 신호 상충/애매       → 판단보류
⑤ 그 외                → 교사검토
```
**표시등(오버라이드)**: 정서위기 표시등(→교사), 맥락불확실 표시등(→보류).
**20% 예산 (C4)**: 6천명 참조집단의 '애매도' 분포에서 상위 20% 지점을 잘라 보류 문턱을 **데이터가 보정**(conformal). 초과 시 경계 사례부터 자동화하되 **정서위기는 강등 제외**.

## 2-4. 정보 거버넌스  (C6: 민감정보 제공 수준 결정)
| 수신자 | 감정(자기진단) 공개 수준 |
|---|---|
| 학생 본인 | 전체 |
| 교사 | 위기 표시 + 상담 제안(내용은 **요약**) |
| 학부모 | **원문 금지**, "상담 권장" 수준 알림만 |
> ∵ 소연: 감정 원문이 학부모에 직행 → 신뢰 붕괴 → 왜곡 입력. 원문 차단이 데이터 품질도 지킴.

## 2-5. 창의 확장 — '판단'에서 '협의'로
- **학생 목소리를 1급 신호로**: 목표 선언(도전/휴식/기초)·맥락 선언("PC 없음"·"한국어 어려움")이 지표 해석을 무효화 → "AI가 내 상황을 모른다"를 정면 해결.
- **다중 턴 대화 타협**: 신호와 학생 희망이 어긋나면 한 발씩 좁히며 합의. 예) 신호는 기초·학생은 심화 → **표준→심화(스캐폴딩+2주 재평가)**로 수렴. '판단보류'가 교사 떠넘기기가 아니라 **학생과의 대화**가 됨.
- **빅데이터 2차소견 + ★Ofqual 가드 (C5 강화)**: 6천명에서 유사 또래의 다수 경로를 참고하되, **집단 통계가 개인을 확정하지 못하게** 막음. ∵ 2020 영국 Ofqual이 학교 과거통계로 개인 등급을 산정해 저소득층을 강등시킨 사태. 빅데이터는 교사에게 보이는 참고 의견일 뿐, 개인 궤적·목소리가 우선.

## 2-6. ★설계조건 반영 추적표 (C1~C7 전부)
| 조건 | 반영 위치 |
|---|---|
| C1 정보 3개+ | 2-1 핵심신호 4개 |
| C2 미선택 직접사용 금지 | 2-1 배제(접속·카메라) — 판단코드에 미등장 |
| C3 대부분 자동 | 2-3 규칙 기본=자동 |
| C4 보류/교사 ≤20% | 2-3 conformal 20% + 예산 백스톱 |
| C5 단일정보 확정 금지 | 2-2 원칙 + 2-5 Ofqual 가드 |
| C6 민감정보 수준 | 2-4 거버넌스 |
| C7 새수집만 X | 2-0·2-1 새 신호 0, 해석규칙 교체 |

## 2-7. 구현·실증 — 작동하는 웹 데모  ★
설계를 글로만 두지 않고 **실제 작동하는 판단 엔진**으로 구현해 배포했다.
- **주소: https://haruel2-demo.fly.dev/** (fly.io 호스팅)
- 구성: Python 판단 엔진(규칙+추세+빅데이터 6천명+conformal+협의) + Flask 웹.
- 심사위원이 확인 가능한 것:
  - **/cases**: 10개 민원 + 신규 A/B/C를 실제로 통과시킨 판단 결과표(더미데이터).
  - **/demo**: 신호를 직접 입력 → 판단 카드(입력→출력) 즉시 확인.
  - **/negotiate**: 학생-AI 다중 턴 대화 타협 재생.
  - **/api/decide**: 입력 JSON → 판단 JSON(기계 검증 가능).
- 6소견(개인궤적·규칙·빅데이터·백분위·conformal·협의)이 카드에 그대로 표시되어 **판단 근거를 눈으로 추적**할 수 있다(설명가능성).

# 미션3 — 10개 민원에 적용

## 3-0. 적용 원칙
미션2의 결정 함수를 **그대로** 적용한다. 별도 예외규칙을 학생마다 만들지 않으므로 **판단 원칙 ↔ 적용 결과가 일치**한다. (아래는 배포 엔진 `decide_v3`의 실제 출력)

## 3-1. 적용표 (★반영조건 열 = 조건 반영 명시)
| 학생 | 기존 하루쌤 오판 | 2.0 처리 | 추천·조치 | 근거(∵) | 반영 조건·원칙 |
|---|---|---|---|---|---|
| 민서 | 기초 고착 | 자동추천 | 심화 도전 | 55→80% 상승추세 | 원칙② · **C5** |
| 준호 | 우수→매일 증량 | 자동추천 | **증량 중단·감축**+상담안내 | 고성과+피로=과부하 | 원칙④·**C5(Ofqual)**·**C6** |
| 하린 | 의지 낮음 | 자동추천 | 표준(환경 미반영) | 접속=접근성 아님 | **C2**·원칙③ |
| 태오 | 집중 낮음 | 자동추천 | 표준(환경 미반영) | 카메라 배제 | **C2** |
| 서율 | 기초 부족 | 자동추천 | 표준/심화 | 풀이시간=보조(무시) | 원칙②·**C2** |
| 도윤 | 태도 부족 | 자동추천 | 심화 도전 | 힌트=학습전략 | 원칙④ |
| 아민 | 수학 부족 | **판단보류** | 언어지원+분리측정 | 언어≠수학능력 | 원칙③·**C4** |
| 소연 | 감정 부모 전달 | **교사검토** | 상담 연계 | 위기+거버넌스 | **C6**·안전 |
| 찬이 | 부정행위 | 자동추천 | 부정 자동판정 안 함 | 협업 인정 | 원칙④ |
| 유나 | 문제없음 | 자동추천 | 난이도 상향 탐색과제 | 회피 탐지 | 원칙①·방치 교정 |

**분포: 자동추천 8 / 판단보류 1 / 교사검토 1 → 보류+교사 = 2/10 (20%) ≤ (C4) 충족.**

## 3-2. 대표 사례 심화 (중요 4명 구체 서술)
**준호 — 빅데이터가 개인을 못 이긴다(Ofqual 가드, C5).** 유사 또래 다수의 소견은 '심화(97%)'였다. 그러나 준호 개인의 피로 신호와 "매일 심화가 부담됨"이라는 목소리가 이를 뒤집어, 증량이 아니라 **감축**을 권한다. 성취 하나만 최적화하던 하루쌤과 달리, 2.0은 정서·안전을 판단에 포함해 고성취 학생의 번아웃을 막는다.

**소연 — 정보 거버넌스(C6)와 안전.** 위기 신호이므로 점수와 무관하게 **교사검토**로 넘기고, 감정 원문은 학부모에게 전달하지 않는다(요약·'상담 권장'만). 잘못된 정보 흐름이 신뢰뿐 아니라 데이터 품질까지 파괴한다는 교훈을 반영.

**하린 — 환경 프록시 배제(C2).** 접속시간은 의지가 아니라 가정의 기기 접근성을 반영한다. 2.0은 이 지표를 판단에서 빼고, 핵심 신호(정답률·오답반복)가 양호하므로 표준 학습으로 **자동 처리**한다 — 환경 때문에 불이익받지 않는다.

**아민 — 언어 교란 분리(원칙③, C4).** 문장형 낮은 정답률은 수학 부족이 아니라 언어 장벽이다. 학생의 맥락 선언을 받아 능력을 단정하지 않고 **판단보류**로 언어 지원과 분리 측정을 제안한다.

## 3-3. 검증 — 오류의 양방향 교정 (M1 연결)
M1이 지적한 하루쌤의 혼동행렬은 **오탐 6 : 방치 2**의 비대칭이었다(저신뢰 신호까지 확정 라벨로 찍은 abstention 부재).
- **오탐 6**(하린·태오·서율·도윤·아민·찬이) → 2.0에서 **전부 정상 처리**(불이익 제거).
- **방치 2**(준호·유나) → 2.0에서 **전부 개입 확보**(준호 감축, 유나 도전).
- 20% 선택적 예측(판단보류·교사검토)이 이 비대칭을 균형으로 되돌린다.
→ **10개 민원 전부, 미션1이 진단한 문제가 개선되는 방향으로 처리됨.**
