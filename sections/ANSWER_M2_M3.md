## 미션 2 — 하루쌤 2.0의 설계
────────────────────────────────────────────

### 2-0. 설계의 출발점

하루쌤이 일으킨 문제의 뿌리는 수집한 정보가 부족했다는 데 있지 않고, 이미 가진 정보를 잘못 해석했다는 데 있습니다. 그래서 하루쌤 2.0은 새로운 정보를 더 모으는 방향으로 나아가지 않습니다. 이것은 새로운 정보를 계속 수집하는 방식만으로 문제를 해결할 수 없다는 조건(조건 7)과도 맞닿아 있습니다. 대신 우리는 같은 정보를 읽어 내는 규칙 자체를 바꾸었습니다. 하루쌤 2.0을 관통하는 원칙은 다음과 같이 요약됩니다. 인공지능은 신호를 읽어 잠정적인 가설만 세우고, 최종 판단은 규칙과 학생의 목소리와 대규모 데이터의 참고 의견이 함께 만드는 합의로 정해집니다.

### 2-1. 어떤 정보를 사용하고, 어떤 정보를 배제했는가 (조건 1, 조건 2, 조건 7)

우리는 학생의 학습 상태를 판단하는 핵심 신호로 네 가지를 직접 사용하며, 이로써 정보를 세 개 이상 사용하라는 조건(조건 1)을 충족합니다.

| 사용 신호 | 어떤 역할을 하는가 | 왜 그렇게 쓰는가 |
|---|---|---|
| 정답률과 그 추세 | 학생의 수준과 성장 방향을 읽습니다 | 절대값이 아니라 최근의 궤적을 보아야 성장을 놓치지 않기 때문입니다 |
| 오답 반복률 | 이해가 부족한 것인지 단순 실수인지를 구분합니다 | 정답률 하나만으로 능력을 단정하는 일을 막기 위해서입니다 |
| 과제 제출률 | 학습에 꾸준히 참여하는 정도를 봅니다 | 다만 접속 시간과는 분리하여 해석합니다 |
| 자기진단 설문 | 학생의 정서와 피로를 감지합니다 | 정량 지표가 놓치는 맥락을 사람의 진술로 보완하기 때문입니다 |

풀이 시간과 힌트 사용 횟수는 보조 신호로만 활용하며, 다른 신호와 결합할 때에만 의미를 부여합니다. 이 두 지표를 단독으로 사용하지 않는 까닭은, 풀이 시간이 길다는 사실이 서율이나 아민의 경우처럼 능력 부족이 아니라 읽기 속도나 언어 배경에서 비롯될 수 있고, 힌트가 잦다는 사실이 도윤의 경우처럼 결핍이 아니라 학습 전략일 수 있기 때문입니다.

반면 접속 시간과 카메라 집중도는 자동 판단에서 완전히 배제하였으며, 이는 선택하지 않은 정보를 판단에 직접 사용하지 못하게 한 조건(조건 2)을 지키기 위한 조치입니다. 접속 시간을 배제한 이유는, 이 값이 학생의 의지가 아니라 가정에 컴퓨터가 있는지와 같은 환경에 종속되어, 그대로 사용하면 저소득 가정의 학생을 구조적으로 불리하게 만들기 때문입니다. 카메라 집중도를 배제한 이유는, 이 값이 주거 환경에 좌우되는 데다 사생활을 침해하고 추정의 정확도마저 낮아, 오판과 인권 침해의 위험이 가장 크기 때문입니다. 정리하면 하루쌤 2.0은 새로운 신호를 하나도 도입하지 않고 기존 신호의 해석 규칙만을 교체하므로, 조건 7을 근본적인 차원에서 충족합니다.

### 2-2. 다섯 가지 판단 원칙 (조건 5)

하루쌤 2.0은 다음 다섯 가지 원칙 위에서 작동하며, 이 원칙들은 하나의 정보만으로 학생의 의지나 능력, 집중도를 확정하지 못하게 한 조건(조건 5)을 구체화한 것입니다. 첫째, 어떤 판단도 두 개 이상의 신호가 같은 방향을 가리킬 때에만 내립니다. 둘째, 현재의 값보다 최근의 변화 추세를 우선하여, 과거의 낮은 분류에 학생이 갇히지 않게 합니다. 셋째, 환경에 종속된 지표는 능력이나 의지를 판단하는 근거에서 제외합니다. 넷째, 힌트를 참고하거나 친구와 협업하는 행동은 유익할 수 있으므로 부정적인 신호로 보아 자동으로 벌하지 않습니다. 다섯째, 감정과 같은 민감한 정보는 그 공개 범위를 수신자에 따라 통제합니다.

### 2-3. 세 갈래로 나누는 판단 체계 (조건 3, 조건 4)

하루쌤 2.0은 각 학생을 자동추천, 판단보류, 교사검토의 세 유형 가운데 하나로 처리합니다. 이 결정은 아래의 규칙이 정하며, 규칙은 부작용이 없는 순수한 함수이므로 같은 입력에 대해서는 언제나 같은 결과를 돌려줍니다.

```
① 정서위기 신호가 있으면        → 교사검토  (안전을 최우선으로 두며, 어떤 목소리로도 뒤집을 수 없습니다)
② 맥락이나 언어가 불확실하면    → 판단보류  (정보가 충분하지 않기 때문입니다)
③ 두 개 이상의 신호가 일치하고   → 자동추천  (대부분의 학생이 여기에 해당합니다)
   추세가 뚜렷하면
④ 신호가 서로 상충하거나 애매하면 → 판단보류
⑤ 그 밖의 경우                  → 교사검토
```

이처럼 기본 경로를 자동추천으로 두었으므로, 대부분의 학생에게 스스로 추천을 제공하고 교사가 전원을 검토하지 않게 한 조건(조건 3)을 충족합니다. 아울러 판단보류와 교사검토를 받는 학생이 전체의 20퍼센트를 넘지 못하게 한 조건(조건 4)은 두 겹으로 보장합니다. 먼저 6천 명 규모의 참조 집단에서 판단이 애매한 정도의 분포를 구한 뒤, 그 상위 20퍼센트에 해당하는 지점을 보류의 문턱으로 삼아, 20퍼센트라는 한도를 사람이 임의로 정하지 않고 데이터가 스스로 보정하도록 하였습니다. 만약 이 한도를 넘으면 경계에 놓인 사례부터 자동추천으로 되돌리되, 정서위기로 분류된 학생만은 그 대상에서 제외합니다.

### 2-4. 민감한 정보를 누구에게 어디까지 공개할 것인가 (조건 6)

감정처럼 민감한 정보에 대해서는 수신자에 따라 공개 수준을 다르게 설계하였으며, 이는 민감정보의 제공 범위를 정하라는 조건(조건 6)에 대한 답입니다.

| 수신자 | 감정 정보를 어디까지 공개하는가 |
|---|---|
| 학생 본인 | 전체를 공개합니다 |
| 교사 | 위기 여부를 표시하고 상담을 제안하되, 내용은 요약된 형태로만 전달합니다 |
| 학부모 | 원문은 전달하지 않고, 상담을 권한다는 수준의 알림만 제공합니다 |

이렇게 설계한 까닭은 소연의 사례에서 드러납니다. 소연이 입력한 감정 표현이 학부모에게 원문 그대로 전달되자 신뢰가 무너졌고, 그 뒤로 소연은 자기 상태를 솔직하게 입력하지 않게 되었습니다. 원문을 차단하는 조치는 학생을 보호할 뿐 아니라, 결과적으로 데이터의 품질까지 지켜 줍니다.

### 2-5. 창의적 확장: 판단에서 협의로

하루쌤 2.0의 가장 두드러진 특징은, 인공지능이 일방적으로 판단하는 대신 학생과 협의한다는 데 있습니다.

첫째, 우리는 학생의 목소리를 판단의 일차적인 근거로 삼았습니다. 학생은 자신의 목표를 스스로 밝히고(더 도전하고 싶다, 조금 쉬고 싶다, 기초부터 다지고 싶다), 자신의 맥락을 직접 선언합니다(집에 컴퓨터가 없다, 한국어 문장이 어렵다). 이러한 선언은 신호에 대한 잘못된 해석을 무효로 만듭니다. 이것은 "인공지능이 내 상황을 이해하지 못한다"라는 학생들의 근본적인 불만에 대한 직접적인 답입니다.

둘째, 신호가 가리키는 방향과 학생이 바라는 방향이 어긋날 때에는 여러 차례 대화를 주고받으며 타협점을 찾습니다. 예를 들어 신호는 기초를 권하지만 학생이 심화를 원한다면, 하루쌤은 표준 단계를 거쳐 심화로 한 걸음씩 다가가되 보조 설명과 2주 뒤의 재평가라는 안전장치를 함께 제시하여 합의에 이릅니다. 이로써 판단보류는 교사에게 책임을 전가하는 막다른 길이 아니라, 학생과 나누는 대화가 됩니다.

셋째, 우리는 대규모 데이터에서 유사한 학생들의 경로를 참고하되, 집단의 통계가 개인을 확정하지 못하도록 막는 장치를 두었습니다. 이 장치를 우리는 오프퀄 안전장치라고 부릅니다. 2020년 영국의 오프퀄이 시험을 취소한 뒤 학교의 과거 통계로 개인의 등급을 산정하였다가 저소득층 학생을 대규모로 강등시킨 사건은, 대규모 데이터를 개인의 확정에 사용하는 일이 얼마나 위험한지를 보여 줍니다. 따라서 하루쌤 2.0에서 대규모 데이터는 교사에게 제시되는 참고 의견에 머무르며, 개인의 궤적과 목소리가 언제나 우선합니다.

### 2-6. 설계 조건이 어디에 반영되었는가

앞서 설명한 내용이 일곱 가지 설계 조건에 각각 어떻게 대응하는지를 아래 표에 정리하였습니다.

| 조건 | 반영된 위치 |
|---|---|
| 조건 1 (정보 3개 이상) | 2-1의 핵심 신호 네 가지 |
| 조건 2 (미선택 정보 직접 사용 금지) | 2-1에서 접속 시간과 카메라를 판단에서 배제 |
| 조건 3 (대부분 자동 추천) | 2-3의 규칙에서 기본 경로를 자동추천으로 설정 |
| 조건 4 (보류와 교사검토 20퍼센트 이하) | 2-3의 데이터 기반 20퍼센트 보정과 예산 장치 |
| 조건 5 (하나의 정보로 확정 금지) | 2-2의 다섯 원칙과 2-5의 오프퀄 안전장치 |
| 조건 6 (민감정보 공개 수준 결정) | 2-4의 수신자별 공개 설계 |

### 2-7. 설계에 그치지 않고, 실제로 구현하여 배포하였습니다

우리는 하루쌤 2.0을 문서상의 설계로만 남겨 두지 않았습니다. 위에서 설명한 판단 규칙을 실제로 작동하는 파이썬 엔진으로 구현하였고, 이를 학생이 직접 사용해 볼 수 있는 학습 플랫폼으로 만들어 fly.io에 배포하였습니다. 심사위원께서는 아래 주소에 접속하여 지금 바로 작동을 확인하실 수 있습니다.

**https://haruel2-demo.fly.dev/**

판단의 핵심은 다음과 같은 규칙 함수로 구현되어 있으며, 이 함수는 부작용이 없으므로 같은 입력에 대해서는 언제나 같은 결과를 돌려줍니다. 아래는 실제 소스 코드의 일부입니다.

```python
def ai_hypothesis(s):
    acc, tr = s.acc_hist[-1], slope(s.acc_hist)     # 현재 정답률과 추세
    if s.self_report == "crisis":                   # ① 정서위기 → 사람에게(안전 최우선)
        return dict(kind="교사검토", rec="정서 상담 연계 + 학습량 감축", ...)
    if s.self_report == "tired" and acc >= 0.85:    # ② 고성과+피로 → 증량이 아니라 감축
        return dict(kind="자동추천", rec="증량 중단 → 학습량 감축", ...)
    if s.collab_flag:                               # 협업 → 부정행위로 자동 판정하지 않음
        return dict(kind="자동추천", rec="부정행위 자동판정 안 함(협업 인정)", ...)
    if tr >= 0.03 and s.submit_rate >= 0.6:         # 성장 추세 → 상향(라벨 고착 배제)
        return dict(kind="자동추천", rec="심화 도전" if acc>=0.7 else "표준 학습(상향)", ...)
    ...
```

이 엔진이 실제로 판단을 내리는 모습은 배포된 서버에 요청을 보내어 그대로 확인할 수 있습니다. 예를 들어 준호의 신호(정답률 92퍼센트, 피로 신호, "매일 심화가 부담된다"라는 목소리)를 보내면, 서버는 다음과 같이 응답합니다.

```
입력 → 정답률 [0.90, 0.91, 0.92, 0.92] · 자기진단 '피로' · 목표 '휴식'
출력 → 처리: 자동추천 / 조치: 학습량 감축과 회복 루틴
       또래 6천 명의 다수 의견: 심화 (97%)   ← 그러나 개인의 판단을 뒤집지 못함
       근거: 정답률은 높으나 피로가 겹쳐 과부하이기 때문
```

또래 6천 명의 다수 의견은 심화를 향해 있었지만 준호 개인의 신호와 목소리가 이를 이겼다는 사실이 응답에 그대로 드러나며, 이것이 오프퀄 안전장치가 실제로 작동한 장면입니다.

심사위원께서 플랫폼에서 직접 해 보실 수 있는 것은 다음과 같습니다. 학생 한 명을 골라 로그인하면 하루쌤의 오늘 추천을 받고, 문제를 풀면 그 결과에 따라 추천이 실제로 바뀌는 것을 볼 수 있습니다. 하루쌤과의 대화 화면에서 "조금 쉬고 싶어요"나 "집에 컴퓨터가 없어요"와 같은 버튼을 누르면, 그 목소리가 반영되어 추천이 즉시 조정됩니다. 선생님 화면으로 넘어가면 검토가 필요한 학생이 표시되는데, 이때 위기 학생의 감정 원문은 가려지고 상담을 권한다는 표시만 나타나므로, 앞서 설명한 정보 거버넌스가 실제로 구현되어 있음을 확인하실 수 있습니다.

### 3-2. 대표 사례에 대한 상세한 설명

준호의 사례는 대규모 데이터가 개인을 이기지 못한다는 원칙을 잘 보여 줍니다. 유사한 또래들의 다수 의견은 심화를 향해 있었으나, 준호 개인의 피로 신호와 "매일 심화가 부담된다"라는 목소리가 이를 뒤집어, 학습량을 늘리는 대신 줄이도록 이끌었습니다. 성취 지표 하나만을 최적화하던 기존 하루쌤과 달리, 하루쌤 2.0은 정서와 안전을 판단에 포함하여 성적이 우수한 학생의 번아웃까지 막습니다.

소연의 사례는 정보 거버넌스와 안전이 함께 작동하는 모습을 보여 줍니다. 위기 신호가 감지되었으므로 점수와 관계없이 교사에게 넘기며, 감정의 원문은 학부모에게 전달하지 않고 상담을 권하는 수준의 알림만 제공합니다. 잘못된 정보의 흐름이 신뢰뿐 아니라 데이터의 품질까지 무너뜨린다는 교훈을 반영한 것입니다.

하린의 사례는 환경에 종속된 지표를 배제하는 원칙이 형평성을 지키는 과정을 보여 줍니다. 접속 시간은 학생의 의지가 아니라 가정의 기기 접근성을 반영하므로, 하루쌤 2.0은 이 지표를 판단에서 제외합니다. 핵심 신호인 정답률과 오답 반복률이 양호하므로 표준 학습으로 자동 처리하며, 그 결과 하린은 환경 때문에 불이익을 받지 않습니다.

### 3-3. 오류가 양방향으로 교정되었는가

미션 1의 분석에 따르면 기존 하루쌤은 정상을 문제로 오인한 거짓양성이 여섯 건, 문제를 정상으로 놓친 거짓음성이 두 건으로 나타나, 오류가 한쪽으로 치우쳐 있었습니다. 그 원인은 신뢰도가 낮은 신호까지 확정된 라벨로 찍어 버린 데 있었습니다. 하루쌤 2.0은 이 치우침을 바로잡습니다. 거짓양성으로 분류되었던 여섯 명(하린, 태오, 서율, 도윤, 아민, 찬이)은 모두 정상적으로 처리되어 불이익에서 벗어났고, 방치되었던 두 명(준호, 유나)은 모두 필요한 개입을 받게 되었습니다. 판단보류와 교사검토라는 선택적 유예가 이 균형을 회복시킵니다. 결론적으로 열 건의 민원 모두에서, 미션 1이 진단한 문제가 개선되는 방향으로 처리되었습니다.
