# CPS 본선 현장 운영 매뉴얼 (3인 팀 · 코워크)

목표: **손으로 쓸 보고서를 빠르게 만든다.** 에이전트는 개조식 뼈대와 손그림 설계도만 뽑고, 우리는 옮겨 적고 그린다. 깃허브로 안 겹치게 나눠 작업하며, 동기화는 데몬이 자동으로 한다.

## 0. 대회 전에 반드시 (집에서 미리)
- [ ] 규정상 **노트북·인터넷·AI(코워크) 사용이 허용되는지** 먼저 확인. 안 되면 이 환경 못 씀.

- [ ] 3명 모두 `git clone` → `git config user.name` 각자 이름으로 설정 → push 테스트
- [ ] `./sync.sh &` 띄우고 파일 하나 고쳐 **자동 push/pull 되는지** 3명이 확인
- [ ] 코워크 데스크탑에서 이 폴더 열어 `CLAUDE.md` 인식되는지 확인, 모의고사로 1회 예행
- [ ] 역할(A/B/C) 확정

### 리포 올리기 (한 명만)
```bash
cd ~/Downloads/cps-bonseon

gh repo create cps-bonseon --private --source=. --remote=origin --push
```

## 1. 자동 동기화 (핵심)
각자 자기 컴퓨터 터미널에서 **한 번만** 띄운다:
```bash
./sync.sh &        # 15초마다 pull → commit → push 자동
```
- 이후 git 명령을 **손으로 칠 필요 없음.** 파일만 저장하면 데몬이 알아서 동기화.
- 에이전트에게도 "git 직접 만지지 말고 파일만 편집" 규칙 지정(`CLAUDE.md`에 있음) → 이중 커밋 경합 방지.
- 충돌 뜨면 데몬이 `⚠️ 충돌` 출력 → 같은 파일을 둘이 고친 것. 담당자가 정리.
- 진행 확인: `git log --oneline -10` 또는 GitHub 웹 커밋 목록(실시간).

## 2. 역할 분담 — "각자 전체를 풀지" 않는다
> 셋이 각자 에이전트로 전체를 풀면 핵심 전략이 3개로 갈려 합칠 때 대충돌 + 재작업.
> 창의문제는 **하나의 일관된 논리**가 점수다. 그래서 아래처럼 **수렴 → (범위 나눈) 발산 → 수렴**으로 간다.
> 그리고 에이전트는 **초안·검증**, 사람 손은 **판단·필기**.

### Phase 0 · 공동 확정 (첫 10~15분, 함께 · 에이전트 1개)
- 전원이 한 화면으로 브레인스토밍 → **핵심 전략 1개 + 핵심 가정 3~4개**를 `SPINE.md`에 락.
- 여기서 안 맞추면 뒤가 전부 어긋남. **가장 중요한 단계.**

### Phase 1 · 분업 심화 (병렬 · 각자 에이전트 · SPINE 기준)
기능으로 나눈다(섹션 슬라이스 X → 관점이 달라 덜 겹침):

| 팀원 | 페르소나 | 소유 파일 |
|---|---|---|
| **A 리드/편집** | 논리 일관성·취합 | `SPINE`, `01_원인`, `04_선택_로드맵`, `FINAL` |
| **B 분석/비판** | 비교·레드팀 | `02_대안비교`, `05_갈등_효과` |
| **C 모델/시각** | 수치·그림 | `03_가정_시나리오`, `visuals/` |

- 각자 자기 에이전트에 "너는 역할 A/B/C" 지정 → 에이전트가 `roles/*.md` 읽고 그 파일만 작업.
- **한 파일 = 한 사람** → 동기화 충돌 원천 차단.

### Phase 2 · 취합·검증 (A 주도)
- A가 `FINAL.md`로 모음 / B가 반론 점검 / C가 시각자료 마감.

### Phase 3 · 손 필기 (전원 병렬 — 여기가 진짜 병목)
- 사람 손이 느리다. 페이지·섹션 나눠 **동시에** 옮겨 적고 그림. 에이전트는 오탈자·누락 점검만.

---

## 3. 현장 골든룰
1. 내 파일만 편집(남의 파일 읽기만). `SPINE.md`는 A만.
2. `BOARD.md`는 내 줄만 수정.
3. 저장은 자주 → 데몬이 자주 올린다.
4. 막히면 말로 즉시 공유(채팅/구두). 침묵이 제일 위험.

---

## 4. 파일 안내
- `CLAUDE.md` — 코워크 에이전트 공통 지침(폴더 열면 자동)
- `PROMPT.md` — 웹/폴더 없이 쓸 때 붙일 마스터 프롬프트
- `SPINE.md` — 팀 확정 핵심(모든 작업 기준, A만 수정)
- `roles/` — A/B/C 각자 작업 브리프
- `sections/` — 섹션별 개조식 작성(파일별 1인 소유)
- `visuals/` — 손그림 설계도(각자 파일 분리)
- `BOARD.md` — 진행판  ·  `FINAL.md` — 최종 취합본
- `00_문제.md` — 문제 원문(처음 한 번, 읽기용)
- `sync.sh` — 자동 동기화 데몬
